继续使用已有网页、数据库和附件存储，飞书负责员工身份、组织关系及个人消息。旧群Webhook不再被服务调度。

本版新增
1. 从飞书通讯录预览员工姓名、部门、岗位、在职状态和直属上级，按飞书身份合并到系统。
2. 员工完成全部任务成果、自评和六项典型事例后，点击“提交整月绩效并通知上级”。
3. 提交时读取飞书中的直属上级，发送个人评分待办卡片；点击打开对应员工、对应月份。
4. 首次未评分提交可据飞书关系绑定实际主管；已发生提交或评分后，主管不一致需管理员核对，历史归档不重写。
5. HRBP指定的跨部门验收人收到个人待办；员工被退回时收到补充提醒。
6. 每月前5个工作日默认北京时间09:00，按员工、上级、HRBP和验收人职责发送个人提醒，已完成的事项不重复催办。
7. 消息事件随业务记录保存，服务器发送队列记录结果；短时故障使用相同uuid重试，超过去重窗口的未知结果由管理员核对。
8. 整月提交、退回、通知状态、权限检查、测试卡片、通讯录预览和发送日志均有页面入口。

仍保留的原表与流程
OKR承接目标、任务描述、交付标准、期限、权重、总结、自评、上级评分和备注；任务为10分制，两项上级评分均值，自评仅参考。
原表五项协作各20%；六项核心素质17/17/17/17/16/16%。评分主体按11月2日纪要预填；跨部门评分人按后续确认继续由HRBP指定。
目标主管确认、员工本人确认；多位验收人全部通过；退回重提、目标变更和历史版本。
上级与不同HRD的特殊加分双审批、红线最终归零、总分封顶100、未评与有效0区分。
评分方案草稿与批准规则分开；纪要没有明确的跨任务汇总、无协作处理及双门槛冲突仍须明确后生效。
归档保存明细、关系、规则、计算结果和审计，支持Excel/PDF导出；服务、备份、TLS和飞书登录沿用。

接入顺序
详见 deploy/飞书自建应用接入说明.txt。
1. 在已有自建应用开启机器人及应用身份权限，发布版本；可用范围、通讯录数据范围覆盖实际考核员工与其直属上级。
2. 管理设置 → 飞书自建应用与个人待办 → 检查应用权限与机器人。
3. 发送测试卡片给当前管理员，核对接收。
4. 读取通讯录并预览人数、部门、上级及范围，应用已核对的名单。
5. 在人员管理明确HRBP/HRD关系，再生成考核单。通讯录不能凭HR部门或同名人员推断HRBP/HRD授权。
6. 员工提交任务成果和整月绩效，上级从卡片进入评分。

当前验证
62项程序测试通过，涵盖原表流程、独立算分、权限、身份匹配、主管变更、提交通知、重复触发、退回重提、队列恢复、短时重试、未知结果、个人催办、深链接和子路径。
本地浏览器验证整月提交状态、通知提示、应用接入页面及设置保存；演示环境不读真实通讯录、不发真实消息。
真实飞书推送及全员同步仍需先开通应用权限和机器人能力，不能把模拟接口测试视为真实送达。
目前生产只有首位管理员，未导入虚构员工或规则。真实组织名单可在权限具备后从飞书预览导入；HRBP/HRD仍需企业明确。
全员容量和完整异机恢复仍需试点验证；API不限量不等于系统并发容量无限。
